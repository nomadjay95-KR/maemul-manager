# PRD: 부동산 매물장 관리 시스템

## 1. 개요

### 1.1 배경
공인중개사인 부모님이 빌라/다세대 및 상가 매물을 수기로 관리하고 있어, 고객/타 부동산 문의 응대 시 기억에 의존하는 비효율이 발생하고 있음.

### 1.2 목표
태블릿(iPad, Android)에서 사용하기 편한 웹 기반 매물장 관리 시스템을 구축하여:
- 매물 정보를 체계적으로 등록/관리
- 조건 기반 필터로 빠른 매물 조회
- 문의 이력을 DB화하여 매물-고객 매칭 지원

### 1.3 사용자
- 부모님 2명 (공인중개사)
- 사무실(Wi-Fi) 및 외부(셀룰러) 환경에서 사용

## 2. 기능 요구사항

### 2.1 매물 관리 (핵심)

#### 2.1.1 빌라/다세대 탭

**등록 항목:**
| 항목 | 타입 | 비고 |
|------|------|------|
| 주소 | 텍스트 | 필수 |
| 호수 | 텍스트 | (예: 201호) |
| 방 개수 | 숫자 | 필수 |
| 거래 유형 | 선택 | 월세 / 전세 / 매매 |
| 보증금 | 숫자(만원) | |
| 월세 | 숫자(만원) | 월세인 경우 |
| 전세금 | 숫자(만원) | 전세인 경우 |
| 매매가 | 숫자(만원) | 매매인 경우 |
| 대출 가능 여부 | Y/N | 전세인 경우 |
| 입주 상태 | 선택 | 공실 / 거주중 |
| 이사 예정월 | 월 선택 | 거주중인 경우 |
| 집주인 연락처 | 전화번호 | |
| 임대인 성향 | 텍스트 | (예: 까다로움, 협조적 등) |
| 집 비밀번호 | 텍스트 | |
| 채광 | 텍스트/선택 | (예: 좋음, 보통, 어두움) |
| 수리 상태 | 텍스트 | |
| 연식 | 숫자(년) | |
| 특이사항 | 텍스트(장문) | |
| 메모 | 텍스트(장문) | 자유 기록 |
| 사진 | 이미지 업로드 | 최대 ~10장, 순서 무관 |

#### 2.1.2 상가 탭

**등록 항목:**
| 항목 | 타입 | 비고 |
|------|------|------|
| 주소 | 텍스트 | 필수 |
| 층수 | 텍스트 | |
| 면적 | 숫자(평/m2) | |
| 거래 유형 | 선택 | 월세 / 전세 / 매매 |
| 보증금 | 숫자(만원) | |
| 월세 | 숫자(만원) | |
| 전세금 | 숫자(만원) | |
| 매매가 | 숫자(만원) | |
| 권리금 | 숫자(만원) | |
| 업종 제한 | 텍스트 | (예: 음식점 불가) |
| 임대인 연락처 | 전화번호 | |
| 임대인 성향 | 텍스트 | |
| 입주 상태 | 선택 | 공실 / 사용중 |
| 특이사항 | 텍스트(장문) | |
| 메모 | 텍스트(장문) | |
| 사진 | 이미지 업로드 | 최대 ~10장 |

#### 2.1.3 매물 상태 관리
- **활성**: 현재 중개 가능한 매물 (기본 목록에 표시)
- **계약완료**: 계약 성사된 매물 (목록에서 숨김, 별도 보관함에서 조회 가능)
- 상태 변경은 원클릭으로 가능해야 함

#### 2.1.4 검색 및 필터
- **필터 조건**: 거래 유형(월세/전세/매매), 가격대(범위), 방 개수
- **복합 필터**: 여러 조건 동시 적용 가능
- **텍스트 검색**: 주소, 특이사항 등에서 키워드 검색
- 필터 적용 시 실시간으로 목록 갱신

### 2.2 문의 관리

#### 2.2.1 문의 등록
| 항목 | 타입 | 비고 |
|------|------|------|
| 문의자 이름 | 텍스트 | 필수 |
| 연락처 | 전화번호 | 필수 |
| 문의 사항 | 텍스트(장문) | 원하는 조건 기록 |
| 문의 날짜 | 날짜 | 자동 입력 |
| 응대 결과 | 텍스트 | (예: 매물 3건 안내, 방문 예약 등) |

#### 2.2.2 매물-문의 매칭
- 새 매물 등록 시, 해당 매물 조건과 맞는 기존 문의가 있으면 알림 표시
- 매칭 조건: 거래 유형 + 가격 범위 + 방 개수 (빌라) 또는 거래 유형 + 가격 범위 (상가)
- 매칭된 문의자 목록을 매물 상세에서 확인 가능

---

### 2.3 통화 녹음 분석 (후순위)

- 통화 녹음 파일(.m4a, .mp3 등) 업로드
- AI(STT + 요약)로 자동 분석하여 문의 DB에 저장
- 분석 결과: 문의자 정보, 원하는 조건, 핵심 내용 추출
- 저장 전 사용자가 내용 확인/수정 가능

## 3. 비기능 요구사항

### 3.1 사용 환경
- **반응형 웹**: iPad, Android 태블릿에서 최적화
- **터치 친화적 UI**: 큰 버튼, 충분한 터치 영역, 스크롤 자연스러움
- **오프라인 접근**: 인터넷 연결 필수 (셀룰러/Wi-Fi 사용 전제)

### 3.2 보안
- 간단한 비밀번호 잠금 (PIN 또는 패스워드)
- 민감 정보 포함 (집주인 연락처, 비밀번호) → HTTPS 필수

### 3.3 성능
- 매물 수: 수십~수백 건 규모 (소규모)
- 사진 업로드: 매물당 최대 10장, 적절한 압축 적용
- 목록 로딩 및 필터 적용: 즉시 반응

## 4. 기술 스택 (제안)

| 구분 | 기술 | 이유 |
|------|------|------|
| 프론트엔드 | Next.js (React) | 반응형 웹, PWA 지원 가능 |
| UI | Tailwind CSS | 빠른 개발, 태블릿 최적화 용이 |
| 백엔드 | Next.js API Routes 또는 Supabase | 소규모 앱에 적합, 빠른 구축 |
| DB | Supabase (PostgreSQL) | 무료 티어, 실시간 지원 |
| 파일 저장 | Supabase Storage | 사진 업로드/관리 |
| 배포 | Vercel | 무료 티어, HTTPS 자동 |
| 후순위 - STT | OpenAI Whisper API | 한국어 녹음 분석 |

## 6. 우선순위 및 개발 단계

### Phase 1 (MVP)
- 매물 CRUD (빌라/상가 탭 분리)
- 사진 업로드
- 검색/필터
- 매물 상태 관리 (활성/계약완료)
- 비밀번호 잠금

### Phase 2
- 문의 DB (등록, 목록, 검색)
- 매물-문의 매칭 알림
- 메모 / 임대인 성향 기록 강화

### Phase 3 (후순위)
- 통화 녹음 파일 업로드 → STT → 자동 문의 등록
- PWA (홈 화면 추가, 앱처럼 사용)

---

## 7. 성공 지표

- 매물 등록/조회가 수기 대비 빠르고 정확함
- 고객/타 부동산 문의 시 30초 내 조건에 맞는 매물 조회 가능
- 문의 이력이 누락 없이 관리됨
